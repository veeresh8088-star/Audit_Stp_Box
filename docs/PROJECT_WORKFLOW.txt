================================================================================
🛡️ AICyberAuditBox — FULL PROJECT WORKFLOW & ROLES GUIDE
================================================================================

This document provides a detailed overview of the different user roles (Admin, 
Auditor, Auditee) and the step-by-step 5-Stage Agentic RAG Audit Pipeline in the 
AICyberAuditBox application.

--------------------------------------------------------------------------------
👥 USER ROLES & THEIR CAPABILITIES
--------------------------------------------------------------------------------

1. 🔐 ADMIN (System Administrator)
   --------------------------------
   * Purpose: Platform infrastructure setup, AI engine selectability, safety monitoring, 
     and full database cleanup.
   
   * Available Dashboard Tabs:
     - 💬 AI Assistant: Chat directly with the local AI.
     - 📊 Audit Report: Inspect findings, compliance status, and severity cards.
     - 🗄️ Audit Records: View raw database findings.
   
   * Exclusive Admin Permissions:
     - Select Local LLM: Change the active AI engine (Qwen 2.5 3B/7B, Llama 3.1 8B, 
       Gemma 2 9B, or Escalation Mode).
     - Clear Database Records: Wipes all findings, reports, uploaded files, and 
       checkpoints to completely reset the system.
     - Monitoring & Logs (at bottom of screen):
       * ⚡ System Events: Live log of DB errors, Ollama failovers, and force-saves.
       * 📋 Audit Trail: Privacy-safe event log tracking user logins and system queries.
     - 2FA QR Seeding: Auto-seeded admin user details (username: admin / password: admin123)
       with direct visual QR code scanning setup for TOTP 2FA.

2. 📋 AUDITOR (Compliance Auditor)
   ---------------------------------
   * Purpose: Directs the audit execution, manages scope, uploads references, reviews/edits 
     findings, and publishes the final report.
   
   * Available Dashboard Tabs:
     - 💬 AI Assistant: Prompts the offline LLM to analyze loaded compliance text.
     - 📊 Audit Report: View findings, evidence snippets, and recommendations.
     - 🗂️ Audit Documents: View and manage currently loaded memory files.
     - 📋 Submitted Reports: Open historical reports, delete, or download PDF reports.
     - 🗄️ Audit Records: Export active findings to CSV, remove individual records, 
       and target/publish the active audit session to a specific Auditee.
   
   * Active Scoping Features:
     - Target Framework: Select active standards (ISO 27001, SOC 2, GDPR, BCMS, X-BOM) 
       which maps to specific subsets of the 93 ISO 27001 Annex A controls.
     - Scoping Mode: Automatic AI Scoping (LLM auto-detects target controls based on documents) 
       or Manual Scoping (selecting custom document templates to check).

3. 🗂️ AUDITEE (Auditee / Client)
   ------------------------------
   * Purpose: Submits evidence documents and reviews final published reports.
   
   * Available Dashboard Tabs:
     - 📤 Upload Evidence: Upload security/policy documents (.pdf, .docx, .zip, .xlsx, .csv, 
       .png, .jpg, .txt), select specific files, and submit them to the auditor. 
       This transitions the report status to "Pending Review".
     - 📋 Submitted Reports: View completed, published reports from the Auditor in 
       a read-only view and download final reports as PDF.
   
   * Restrictions:
     - No access to active chat assistants, LLM engine setup, database cleanup, or scoping 
       configuration pages.

--------------------------------------------------------------------------------
🔄 THE END-TO-END AUDIT PIPELINE (RAG WORKFLOW)
--------------------------------------------------------------------------------

1. EVIDENCE UPLOAD (Auditee)
   The Auditee uploads relevant policies or evidence files (e.g. multi-factor authentication, 
   incident response plan, database backup policies) in their workspace. They select the 
   files and click "Send to Auditor". The report is placed in "Pending Review" status.

2. SCENARIO CONFIGURATION (Auditor)
   The Auditor opens the session. They can upload additional reference documents or 
   auditor guidelines. The Auditor selects the framework (e.g., ISO 27001) and selects 
   whether to use AI-Scoping or Manual scoping to filter the list of controls to audit.

3. SCAN PIPELINE RUN
   The Auditor clicks "Run Analysis" to trigger the 5-stage background RAG scanner:
     - Stage 1: Ingest & Parse: Files are read (using native text extraction or OCR for images).
     - Stage 2: Chunk & Embed: Extracted text is split into chunks and stored.
     - Stage 3: Semantic Mapping: The pipeline locates evidence segments relevant to each target control.
     - Stage 4: Gap Detection: Offline LLM compares evidence against controls to locate non-compliance.
     - Stage 5: Reporting: Formulates severity, recommendations, and evidence snippets.

4. CHECKPOINTING & FAIL-SAFE SAVES
   As the pipeline runs, it saves progress to ShaktiDB after every ~10 controls. If the server 
   crashes, the auditor can reload the session and click "Resume Interrupted Audit" to continue 
   seamlessly from the last completed checkpoint.

5. REVIEW & EDIT (Auditor)
   The Auditor views the interactive findings card list. They can Accept, Modify (re-classify 
   severity/status or edit text), or Delete specific finding cards, and add custom auditor comments.

6. REPORT PUBLICATION
   From the Audit Records dashboard, the Auditor selects the target Auditee and clicks 
   "Send to Auditee". This publishes the report (status changes to "Sent to Auditee").

7. DOWNLOAD & ARCHIVE
   The Auditee views the read-only findings list inside their portal and downloads the 
   final Audit Report in PDF format.
